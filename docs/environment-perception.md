# 环境感知方案

## 1. 目标

让 Agent 像一个「身在世界之中」的主体，持续感知环境，而不是被动等待人工输入。当前版本聚焦 **读屏**，后续扩展为**多视频源**与**语音输入**。

## 2. 当前：读屏（Screen）

### 2.1 为什么先做读屏
- 不需要额外硬件，Windows 自带屏幕。
- 能直接获取「用户在电脑上看到的一切」，是最廉价也最有信息量的环境输入之一。
- 便于后期叠加：既然 Agent 能看屏幕，就能理解用户当前在做什么。

### 2.2 实现思路
1. **屏幕捕获**：用 `mss` 定时截取全屏/指定窗口。
2. **文本提取（OCR）**：对截屏做 OCR，得到屏幕上的文字（Windows OCR API 或 `pytesseract`）。
3. **语义编码**：把「屏幕文本 + 关键区域截图」编码成观测，送入世界状态。

```
[屏幕] --mss捕获--> [图像帧] --OCR--> [文本/区域]
                         └--VLM(可选)--> [语义描述]
                                        └──> 观测 Observation
```

### 2.3 读屏接口设计

```python
class ScreenSensor(Sensor):
    """读屏感知：捕获当前屏幕并提取文字/视觉信息。"""
    def capture(self) -> Observation:
        ...
```

## 3. 后续：多视频源（摄像头等多路）

### 3.1 多视频源抽象
所有视频源统一实现 `VideoSensor` 接口，核心循环只消费 `Observation`，不关心来源。

```python
class VideoSensor(Sensor):
    """视频感知源抽象：摄像头、屏幕、远程流等。"""
    def stream(self) -> Iterator[Frame]:
        ...
```

### 3.2 支持的视频源（规划）
- 本地摄像头（OpenCV）
- 屏幕/桌面捕获
- 远程视频流（RTSP / WebRTC）
- 多路同时采集，做帧级融合（时间对齐、重叠区域去重）

### 3.3 多源融合策略
- **时间对齐**：不同源帧率不同，按时间戳对齐。
- **空间注册**：多摄像头若视野重叠，可做简单拼接。
- **语义融合**：把各源描述交给推理层，由模型判断哪些信息重要。

## 4. 后续：语音输入

### 4.1 目标
让用户/环境的声音成为一种感知源。

### 4.2 实现思路
1. **音频采集**：`sounddevice` / `pyaudio` 录麦克风。
2. **语音转写**：本地 `faster-whisper` 或云端 ASR。
3. **音频事件**：非语音声音（敲门、提示音）作为另一类观测。

```
[麦克风] --采集--> [音频帧] --ASR--> [文本] ---> 观测
                    └--分类--> [声音事件]
```

## 5. 统一感知模型

所有感知源最终都输出一个 `Observation`，它是核心循环的输入契约：

```python
@dataclass
class Observation:
    source: str        # 来源：screen / camera / audio
    timestamp: float
    text: str | None   # 文本描述（OCR/ASR 结果）
    image: Any | None  # 可选图像帧
    metadata: dict     # 其它元信息
```

## 6. 感知源的开关与降级

- **动态注册**：通过配置文件/命令行启用某类传感源。
- **降级**：某传感器不可用（如无摄像头）时，其余源继续工作。
- **采样节奏**：屏幕默认可低频（如 1~2s），语音可事件触发。

## 7. 隐私与安全

- 所有感知默认**本地处理**，除非显式启用云端。
- 采集数据默认不落地（或写入 gitignore 的 `captures/`）。
- 提供「暂停感知 / 只保留必要信息」的开关，尊重用户控制权。
