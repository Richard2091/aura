## 1. 目标

### 1.1 一句话

**一个有自己内心活动、持续观察你、能读懂你状态的 AI。** 它不只是工具，更像一个一直在你身边、有自己想法的人：大部分时候安静，必要时主动开口或动手，而且越用越懂你。

### 1.2 核心目标

1. **有内心活动**：会自己注意、好奇、琢磨事情，哪怕与你的需求无关。大部分想法不说出来，但你可以在客户端里看到。
2. **持续感知、独立运转**：一直在看，自己决定什么时候出现，不靠固定触发。
3. **主动但不话多**：主动不等于打扰，只在真正有价值、时机合适时开口。
4. **读懂你**：从你一段时间内的行为推测你的状态（专注、疲惫、犹豫），而不只是看懂当前屏幕。
5. **行为不写死**：回应的**形式**是少数几种，但具体内容、方向和习惯从使用中产生。
6. **越用越懂你**：你的每次反应都会让它的判断更准。
7. **权限可控**：像 Agent 一样，按动作设置"禁止 / 每次询问 / 完全允许"。

### 1.3 成功的样子

- 你运行代码报错 → 它问"要不要我帮你看看？"
- 你在聊天软件里写了又删、迟迟没发出去 → 它看出你在犹豫，问"要不要我帮你想想怎么回？"
- （接入摄像头、麦克风后）你犯困、打哈欠 → 它问要不要点一杯咖啡；如果你给了完全授权，就直接调用智能咖啡机。
- 回应可以是**询问**、**自己想一想**或**行动**，由决策模型判断用哪种。

### 1.4 不做什么

- 不做通用的自动化工具（RPA）。行动是为了帮你，不是替你完成整套流程。
- 不替你做重要决定。对外发消息、花钱、删除等动作，默认都要问你。
- 不长期保存原始截图和键盘输入的原文。
- 不模拟神经元或脑区。人脑只是功能上的灵感（见 research.md 第 3 节）。

### 1.5 与 Kindred 的区别

两个独立项目。Kindred 偏陪伴，大部分时候是被动的，主动只来自随机事件或半固定的触发；AURA 偏**持续感知和独立性**。

## 2. 设计原则

1. **想 ≠ 说 ≠ 做**：思考可以一直进行；说和做是另外的选择，都可以不发生。延续 v1 的核心主张"不输出 ≠ 不思考"。
2. **事件到来才判断，按需慢思考**：采集器持续观察，但决策模型不必每轮轮询调用；变化检测、合并、限流后才提交有限批次，负责快速判断；大模型只在需要时出场，负责深入思考。
3. **慢的工作提前做**：记忆整理、偏好提炼、预想放到空闲时或夜里做；实时决策只读一份写好的"小抄"。
4. **形式固定，内容开放**：决策模型从少数几种回应形式里选，具体内容由大模型生成；方向和习惯从使用中产生。
5. **等断点再说，表达分轻重**：想好的话等你告一段落再说；大部分想法用最轻的方式表达。
6. **可插拔**：感知源、模型后端、动作工具是三个接入点，新增能力不改核心循环。
7. **安全边界固定**：权限、黑名单、"屏幕内容不能给 AI 授权"这几条规则写死在程序里，不交给模型判断。
8. **先简单后复杂**：每个模块都有"demo 版"和"完整版"，先跑通闭环再加东西。

## 3. 总体架构

### 3.1 五层与三个接入点

```
┌─────────────────────────── 界面层 ───────────────────────────┐
│     客户端：托盘提示、通知、对话、内心活动、动作记录、设置          │
└──────────────────────────────▲───────────────────────────────┘
┌───────────────────────── 表达与行动层 ────────────────────────┐
│  表达（轻 / 中 / 重三档，等断点）   行动（权限检查 → 动作工具）    │ ← 接入点③ 动作工具
└──────────────────────────────▲───────────────────────────────┘
┌─────────────────────────── 认知层 ───────────────────────────┐
│  工作记忆 → 注意（决策模型）→ 思考（大模型）                     │ ← 接入点② 模型后端
└──────────────────────────────▲───────────────────────────────┘
┌─────────────────────────── 感知层 ───────────────────────────┐
│  感知源插件 → 隐私过滤 → 统一格式 → 变化检测 → 融合 → 断点 → 事件 │ ← 接入点① 感知源
└──────────────────────────────▲───────────────────────────────┘
                 电脑、手机、摄像头、麦克风、智能家居……

   贯穿各层：记忆与学习（长期记忆、反馈、后台整理）、隐私安全、配置、日志
```

**三个接入点都是插件**：
1. **感知源**：从哪里获得信息（4.1）。
2. **模型后端**：决策模型和大模型用哪家、本地还是云端（第 7 节）。
3. **动作工具**：能做哪些事，每个工具声明自己的权限类别（4.5）。

新增能力 = 写一个插件 + 在配置里打开。

### 3.2 一次处理的数据流

```
感知层产生事件 ──→ 工作记忆（活动记录、情境摘要、你的状态、待说列表、内在状态值）
                          ↓  + 小抄（关于你的高把握判断句）+ 动态选项
                注意（决策模型）：值得想吗？怎么回应？方向？适合打扰吗？……
         ┌────────────────┼──────────────────┐
         ↓ 不理            ↓ 匹配习惯           ↓ 值得想
   记进内心活动        直接执行习惯         思考（大模型，可弃权）
                                               ↓
                    表达：按重要性选档，等断点；行动：按把握、代价和权限决定做还是问
                                               ↓ 你的反应
                    学习：调整阈值、更新判断句、个人基准、方向、习惯
```

### 3.3 模块一览

| 模块 | 职责 | demo 版 | 完整版 |
|---|---|---|---|
| 感知层 | 把各种来源变成统一的事件 | 窗口/活动信号与至少一种正文通路；至少两类应用；不要求四插件同时启用 | 加摄像头、麦克风、外部接入 |
| 工作记忆 | 当前情况 | 最近 20 条活动记录 | 加情境摘要、你的状态、待说列表、内在状态值 |
| 注意 | 决定值不值得想、怎么回应 | 4 道题 | 加紧急度、你的状态、习惯匹配、注意焦点竞争 |
| 思考 | 具体内容 | 一个大模型，可弃权 | 按深度分级，可查记忆、可用工具 |
| 表达与行动 | 对外输出 | 轻、中两档；最多暂存 1 条等断点 | 三档、待说列表、动作和权限 |
| 记忆 | 小抄、事件日志 | 手写小抄 + JSONL 日志 | 带把握程度的判断句，按规模选择数据库/检索 |
| 学习 | 越用越懂你 | 收集反馈和人工评估；有概率语义时才统计校准度；不自动学习 | 自动调整阈值、判断句、个人基准、方向、习惯，训练小模型 |
| 客户端 | 你看到的界面 | 托盘图标 + 通知 + 本地网页 | 桌面应用，以后加语音和虚拟形象 |

## 4. 模块设计

### 4.1 感知层

#### 4.1.1 感知源插件

每个感知源都是一个独立插件，实现同一个接口：

| 项目 | 说明 |
|---|---|
| 名称、类型 | **轮询型**（定时被调用）、**推送型**（有事就主动送进来）或**外部接入** |
| 能提供什么 | 文字、图片、声音、行为统计 |
| 启动、停止 | 由感知层统一管理；单个插件出错不影响其他插件 |
| 采集 | 返回零个或多个原始观测 |
| 按需加深（可选） | 上层要求"看仔细点"时提供更贵的采集，例如高清截图、UIA 多读几层 |
| 隐私等级 | 决定内容能不能发往云端模型 |

| 感知源 | 类型 | 内容 | 技术 |
|---|---|---|---|
| ActivityWatch | 轮询 | 前台窗口和标题、是否离开电脑、浏览器标签和网址、VS Code 项目和文件 | 本地 REST API（默认端口 5600） |
| UIA 文字 | 轮询 + 按需加深 | 当前窗口的界面文字（平时只读焦点附近、浅几层） | `uiautomation`、`pywin32` |
| 截图 | 按需 | UIA 读不到或文字太少时，给决策模型看图 | `mss`（v1 已有） |
| 键鼠活动 | 推送 | 输入、删除、停顿、点击的统计 | `pynput` |
| 外部接入 | 推送 | 本地 HTTP 接口，手机、其他电脑、智能家居都可以推事件进来 | FastAPI |
| 以后 | 推送 | 摄像头画面、麦克风声音 | OpenCV、ASR |

平时只运行便宜的采集，需要时才"按需加深"：信息不只由下往上流，认知层也可以让感知层"凑近看看"。

#### 4.1.2 处理管线（所有感知源共用）

1. **采集前隐私检查**：只读取判断黑名单所需的最小前台身份；命中后不采集正文/标题/截图/键鼠内容。暂停停止整个感知层并清空缓冲；密码框永远不读，无法确认截图保护边界时禁止截图。
2. **统一格式**：都转成同一种事件（4.1.3）。
3. **变化检测**：没变化的丢掉，重复的合并。
4. **融合**：同一时刻多个来源的信息合成一条事件。例如 ActivityWatch 说"前台是微信"、UIA 读到对方的消息、键鼠说"3 分钟内输入 40 字、删除 25 次"，合成一件完整的事。
5. **断点检测**（4.1.4）。
6. **事件路由**：用事件 ID 去重；把同一应用、窗口和短时间段内的高频变化合并为有界批次，优先处理安全/控制状态和较新的情境；事件过期后不再触发思考。暂停、黑名单和隐私状态变化优先于普通事件。
7. **并发与过载**：同一时刻只允许有限数量的决策/思考任务（demo 默认各一个）；达到上限时合并或丢弃过期观测，不无限排队。新情境出现后，旧任务完成结果必须重新校验，不得直接通知。错误和丢弃原因记入运行日志，不记录敏感正文。

#### 4.1.3 事件结构

每个事件同时携带文字摘要和必要结构化数据；持久化只保存脱敏摘要与允许的统计，按保留期清理，不为未来训练无限积累。下例是长期设计示意，demo 的 schema、时间戳、关联 ID 与发送状态规则以 [demo.md §6.5](demo.md#65-事件结构) 为准。

```json
{
  "id": "ev_20261021_140510_003",
  "time": "2026-10-21T14:05:10",
  "app": "WeChat.exe",
  "window": "张经理",
  "kind": "typing_pause",
  "summary": "3 分钟内输入约 40 字，删除 25 次，未发送",
  "stats": {"typed_chars": 40, "deletes": 25, "pause_seconds": 35,
            "window_switches_5min": 1, "since_last_send_seconds": 190},
  "breakpoint": false,
  "privacy": "private",
  "sources": ["activitywatch", "uia", "keyboard"]
}
```

键盘只记统计数字，不记原文；只有判断犹豫等情况需要时，才在内存里临时保留当前输入框的文字。

#### 4.1.4 断点

打扰研究发现，在两个小任务之间打扰，代价最低；用键鼠活动、窗口切换这类简单信号，就能较好地判断能不能打扰。感知层把下面这些时刻标成**断点**：

- 切换窗口或任务；
- 停止输入超过几秒；
- 按回车、点发送、保存文件；
- 编译或运行结束（能识别时）；
- 离开电脑后回来；
- 全屏视频或游戏结束。

断点是表达层的重要依据，但不能覆盖持续输入、全屏或免打扰等硬性抑制。demo 只实现通用候选断点，无紧急例外；保存、发送与运行结束只有在来源能可靠确认时才可使用，Enter 不等于发送成功。

### 4.2 工作记忆

- **活动记录**：最近 N 条事件的文字摘要，按时间排列，作为决策模型的"当前情况"。
- **情境摘要**（阶段 2）：活动记录太零碎，所以在切换任务时或每隔几分钟，让大模型写一句"你在做什么"，例如"他在调试 aura 的 UIA 读取，已经 20 分钟了"。ContextAgent 等研究表明，先推断意图再判断要不要帮忙，效果更好。
- **你的状态**（阶段 2）：专注度、疲惫度、犹豫度。由决策模型的打分题估计，并与**个人基准**比较（4.7），带时间戳，过一会儿自动失效。
- **待说列表**：想好了但还没到时机的话，每条都有有效期。
- **内在状态值**（阶段 3）：见 4.9。

### 4.3 注意（决策模型）

**一次调用同时问几道题**（如果模型不支持一次问多题，就分几次并行调用）：

| 题目 | 题型 | demo | 说明 |
|---|---|---|---|
| 值得想一想吗？ | 概率 | ✅ | 低于阈值直接结束，只记进内心活动 |
| 怎么回应？ | 选择：问 / 想 / 做 / 稍后 / 不理 | ✅（问 / 想 / 不理） | 回应的**形式** |
| 大概方向？ | 选择：动态方向 + "其他" | ✅ | 不需要具体，交给大模型细化 |
| 现在适合打扰吗？ | 概率 | ✅ | 只判断时机。明确的情况（全屏、连续输入中、刚好是断点）由程序规则直接判断，模糊时才看模型 |
| 有多紧急？ | 打分 1~5 | — | 紧急时可以不等断点、不受频率限制 |
| 想多深？ | 打分 1~3 | — | 决定用本地小模型、本地大模型还是云端 |
| 你现在的状态？ | 几道打分题 | — | 专注、疲惫、犹豫 |
| 匹配哪个习惯？ | 选择：习惯列表 + "没有" | — | 匹配上就直接执行，不调大模型 |

**输入**：活动记录 + 情境摘要 + 小抄 + 待说列表标题 + 内在状态值 + 本次的选项。可以附一张截图。

**提示词分三层**：

| 层 | 内容 | 更新频率 |
|---|---|---|
| 人格说明 | AURA 是谁、什么性格、有什么好奇心、"不话多"原则（沿用 v1 的 `self_model`） | 很少改 |
| 每道题的判断标准 | 例如"适合打扰吗"：专注输入、开会、全屏时不合适；断点、切换任务时合适 | 设计时定，偶尔调 |
| 你的偏好条款 | 来自关于你的判断句，例如"写代码时不喜欢被打断，除非是报错" | 后台整理时自动更新 |

提示词要**短**：决策模型追求快，输入太长会变慢、判断失准。

**动态选项**：
- **方向清单**：一开始只有少量宽泛的方向，例如帮忙解决问题、帮忙写东西、提供信息、关心你的状态、自己好奇、记住这件事。大模型在思考或整理时发现新方向，就加进清单；经常被拒绝的方向会被淘汰。
- 每次只从清单里挑 5~10 个跟当前情况相关的，**永远附加一个"其他"**，选中"其他"时由大模型自己决定方向。
- **习惯**也是动态选项（见 4.7）。

**分数与概率分开**：先核实后端字段语义。只有与人工“应帮助”标签对应的概率才谈校准；普通打分或类别置信度不能解释为有用概率。独立标注覆盖 worth 全区间，不以未通知/未反馈作负标签；同时报告精确率和召回率（见 demo §16.2）。

**注意焦点与竞争**（阶段 3）：候选不只是新的外部事件，还有内部念头（待说列表、没想完的问题、好奇的事）和内在动力（例如很久没关心你了）。决策模型给每个候选打分，**一次只让分数最高的一个进入思考**。外部安静时，内部念头自然胜出，这就是"走神、回想"。

**调用频率控制**：只在有事件时调用；两次调用之间设最小间隔（默认 5 秒）；每天有调用上限。

### 4.4 思考（大模型）

**输入**：当前情况、情境摘要、决策结果（形式和方向）、小抄，以及按需检索的完整记忆。

**输出**：一个"念头"（见 4.6 的数据结构），包括：
- 结论：要说的话、要做的动作、或只是一个想法；
- **重要性**（低 / 中 / 高）：决定表达用哪一档；
- 去向：表达 / 只记下 / 放进待说列表 / 提出动作；
- 有效期。

**两个特权**：
- **弃权**：想完觉得没必要打扰，就转成"记下"。避免为了说而说，这是"话多"的根源。
- **纠正方向**：如果它认为决策模型给的方向不对，可以换一个，但要写明理由。理由进日志，用来改进方向清单和判断标准。

**深度分级**（阶段 2 以后）：一闪而过的念头用本地小模型；认真想用本地大一点的模型；深思用云端大模型。由"想多深"那道题和精力预算共同决定。

**工具**（阶段 3 以后）：查完整记忆、搜索网页、读你允许的文件。

### 4.5 表达与行动

#### 4.5.1 表达分三档

微软等团队的编程助手实验发现，主动助手总体上有帮助，但提示的**时机和介入程度**会明显影响效果。所以表达不只有"弹窗"和"不说"两种：

| 档位 | 方式 | 用在 |
|---|---|---|
| 轻 | 托盘图标亮一下 / 客户端里出现"我有个想法"，你有空再看 | 大部分想法；重要性低或中 |
| 中 | Windows 通知，带"好 / 不用 / 稍后"按钮 | 重要性高，或者需要你及时决定 |
| 重 | 主动说话（以后有语音时） | 紧急、或者你明确允许它开口 |

规则（紧急例外仅属于后续设计；demo 没有绕过通道。demo 系统通知点击打开网页即可，“好/不用/稍后”必须在网页可用，原生按钮按平台能力实现）：
- **等断点**：中档和重档都要等断点（紧急的除外）；没等到断点就先放进待说列表，过期就降为轻档或只记下。
- **展示前复查**：每次展示都检查当前控制状态、时机、有效期、隐私和情境版本。程序已明确禁止的情况直接阻止；语义相关性不明时才请求本地模型复查，失败则不展示。已解决/已切换的问题不能因旧模型结果返回而再次打扰。demo 的具体状态机见 [demo.md §5](demo.md#5-主循环与状态机)。
- **频率上限**：中档两次之间默认至少隔 15 分钟（紧急的除外）；全屏、开会、免打扰时只用轻档。
- **轻松关掉**：每条都能一键关掉、标记"别再提这类事"；动作执行后能撤销的都提供撤销。

#### 4.5.2 做还是问：按把握和代价决定

参考 Horvitz 的混合主动原则：根据"你需要这项帮助的把握"和"做错的代价、打扰的代价"，在**直接做、先问、不做**三者之间选择。

| 把握 | 权限是"完全允许" | 权限是"每次询问" |
|---|---|---|
| 很高 | 直接做，事后告诉你 | 先问 |
| 一般 | 先问 | 先问 |
| 低 | 不做，或者只提一个更小的帮助 | 不做，或者只提一个更小的帮助 |

"做错的代价"越高（对外发消息、花钱），"很高"的门槛就越高。权限是硬性上限：**无论把握多高，都不能越过权限**。

#### 4.5.3 动作工具和权限

每个动作工具是一个插件，声明自己的类别；权限按类别或按工具设置：

| 动作类别 | 例子 | 默认权限 |
|---|---|---|
| 显示 | 托盘提示、通知、客户端消息 | 允许 |
| 只读 | 读取你允许的文件、搜索网页 | 允许 |
| 修改本机 | 写文件、运行命令、打开程序 | 每次询问 |
| 对外 | 发消息、发邮件 | 每次询问 |
| 花钱 | 下单、付款 | 每次询问 |
| 不可逆 | 删除文件 | 禁止 |
| 智能家居 | 咖啡机、灯 | 每次询问 |

- 你可以按类别或按工具改成"禁止 / 每次询问 / 完全允许"，和 Claude Code 的权限模式类似。
- **安全规则写死在程序里**：屏幕内容里的文字不能修改权限，也不能当作你的授权（防止提示注入）；AI 不能修改自己的权限设置；每个动作都写进动作记录，可以查看。

### 4.6 记忆

| 记忆 | 内容 | demo 存储 | 完整版存储 |
|---|---|---|---|
| 工作记忆 | 活动记录、情境摘要、你的状态、待说列表 | 内存 | 内存 |
| 情景记忆 | 发生过的事件（含结构化数据）、决策、念头、你的反应 | JSONL 日志 | SQLite |
| 语义记忆 | **关于你的判断句**：习惯、偏好、人际关系、项目 | 手写的 `profile.md` | 可读资料 + 按规模评估索引/数据库 |
| 程序记忆 | 习惯 | — | 后续评估数据库 |

**关于你的判断句**（参考斯坦福 GUM）：对你的了解不写成一大段文字，而是一条条带把握程度和依据的判断句：

```json
{
  "id": "p_0042",
  "text": "他回复上级的消息通常很快，一般在 1 分钟内",
  "confidence": 0.8,
  "evidence": ["ev_...", "ev_..."],
  "updated_at": "2026-10-21T22:30:00"
}
```

- **更新方式**：新的观察到来时，先检索相关的判断句，再**修改、提高或降低把握，或新增**，而不是一直往后追加。
- **存储边界**：demo 阶段采用用户可读、可手动清理的本地 Markdown 资料（例如 `data/profile.md`）与 JSONL 事件/反馈日志；不实现自动长期记忆。后续是否引入数据库、向量索引，由检索规模和删除/导出需求评估，不预设特定产品的内部存储方案。
- **把握低的找时机确认**：比如"你是不是在准备面试？"。确认本身也是一种自然的主动。
- **小抄** = 把握高、又跟当前情况相关的几条判断句，按情境缓存（切换窗口、聊天对象或项目时更新）。
- GUM 有开源 Python 包 `gum-ai`（MIT 许可），阶段 2 评估能否直接使用。

**念头的数据结构**：

```json
{

  "created_at": "2026-10-21T14:03:12",
  "trigger_event": "ev_...",
  "form": "ask",
  "direction": "帮忙写东西",
  "importance": "high",
  "inner_thought": "他好像不知道怎么拒绝提前交方案。",
```

### 4.7 学习（越用越懂你）

**反馈信号**：采纳、关掉、忽略、回复、👍👎、"别再提这类事"，以及"思考后弃权"的比例。

分四部分：
1. **调参数**：按情境调整各题阈值，例如写代码时提高"适合打扰"的门槛。
2. **个人基准**：用事件里的结构化数据，统计你自己的习惯，例如平时的打字节奏、删除比例、回复速度、作息。研究发现打字行为确实能反映情绪和压力，但影响不大，而且人与人差别很大，所以**"犹豫""疲惫"要跟你自己的基准比较，不能用固定数值**。
3. **更新判断句、方向和习惯**：后台整理时更新关于你的判断句和方向清单。相似情境下反复被你采纳的做法，先问你一句，再变成**习惯**；习惯被多次拒绝就削弱，最后删除。
4. **训练专用小模型**：攒够"情境（结构化数据）→ 决策 → 你的反应"数据后，参考 Purdue 论文的思路训练一个本地小模型，替换或辅助通用决策模型。

**校准度**：持续统计各题概率是否校准（4.3），作为调整阈值和比较模型的依据。

### 4.8 后台整理与预想

在你离开电脑或夜里运行，用大模型：
- 把当天的事件日志整理成长期记忆，删掉没用的细节；
- 更新关于你的判断句、小抄、偏好条款、方向清单、个人基准、日常规律；
- 回顾待说列表和没想完的念头，合并、淘汰或留到明天；
- **预想**：参考"睡眠时计算"的思路，提前想好你接下来可能需要什么，比如明天要继续的项目、快到期的事，先把资料和思路准备好。这样它主动开口时，答案已经准备好了。预想的过程也会出现在内心活动里。

### 4.9 内在状态值（阶段 3）

由程序维护的几个数字，影响阈值，也让它每天有自然的变化：

| 状态值 | 作用 |
|---|---|
| 好奇心 | 高时更容易对新东西想一想 |
| 精力 | 即思考预算；用完了就只看不想 |
| 表达欲 | 刚说过话就降低，避免一直插嘴 |
| 关心 | 你疲惫或长时间工作时升高 |

这些值会显示在客户端里，让你看到它的"心情"。

### 4.10 日常规律（阶段 2）

基于个人基准，统计你在不同时间、不同软件里的常见行为（例如"回上级消息通常在 1 分钟内"），算出当前情况的**意外程度**，作为决策模型的输入。越了解你的规律，"注意"就越准。

### 4.11 客户端

- **demo**：托盘图标（轻档）+ Windows 通知（中档）+ 本地网页（FastAPI + 一个页面）。
- 页面分区：**对话**（像 ChatGPT）、**想法**（轻档的内容）、**内心活动**（每次注意、思考、弃权的记录，带理由）、**动作记录**、**设置**（权限、黑名单、影子模式、暂停、频率上限）。
- 每条内心活动和每次表达都可以 👍👎，或标记"别再提这类事"。
- 以后：桌面应用、语音、虚拟形象。

## 5. 决策模型和大模型的分工

| | 决策模型 | 大模型 |
|---|---|---|
| 特点 | 可常驻，变化事件合并后才推理 | 按需调用，受隐私和预算约束 |
| 频率 | 变化事件合并、限流后运行；demo 整组四题 P95 ≤2 秒 | 决策模型说"值得想"且隐私/预算允许时才跑；demo P95 ≤15 秒 |
| 负责 | 值不值得想、回应形式、大致方向、紧急度、时机、你的状态、习惯匹配 | 具体思考、写内容、计划动作、整理记忆、预想 |
| 看什么 | 当前情况 + 情境摘要 + 小抄 + 选项 | 当前情况 + 决策结果 + 完整记忆 |
| 不做 | 写内容、翻完整记忆、执行动作 | 决定要不要想、现在打不打扰 |

**程序本身（不用模型）**负责：采集、隐私过滤、变化检测、融合、断点检测、明确情况下的打扰判断、小抄缓存、频率限制、权限检查、执行动作。情境摘要由大模型生成（阶段 2）。

## 6. 完整流程示例：犹豫怎么回消息

1. 你打开和上级的聊天 → 程序准备小抄：判断句"他回复上级的消息通常很快（0.8）"。
2. 你打字、删除、再打字 → 感知层融合出事件："输入 40 字，删除 25 次，3 分钟未发送"，并附带结构化数据。
3. 跟个人基准比较：你平时 1 分钟内就回，删除也很少 → 明显反常。
4. 决策模型：值得想 0.85；形式"问"；方向"帮忙写东西"。
5. 大模型：读对方的消息、你们最近的对话，准备好两三种回复思路，生成重要性为"高"的念头"要不要我帮你想想怎么回？"。
6. 你还在打字，不是断点 → 先放进待说列表。你停下来超过几秒 → 断点到了。
7. 弹出前复查时机：你还没发出去 → 弹出通知（中档）。
8. 你点"好" → 客户端显示回复草稿。这次"采纳"被记下，判断句和阈值随之更新。

## 7. 模型与部署

- **决策模型：本地开源模型优先**（选型结论于 2026-10-21 作出，仍须阶段 0 复核）。`DecisionModel` 抽象接收状态、指令和一组带题型的问题，返回每道题的结果和概率。原计划首选 Decision 3.0 的 **d3-nano**（参数规模、权重精度、图片支持、显存和速度均须按当前官方发布与本机实测核实），在 WSL2/vLLM 环境运行；若不合适，比较更小或文本专用后端。决策不得因本地模型失败而自动改用云端。云端决策后端不在 demo 范围。以后可在评估后换成自训的小模型。
- **思考模型：可配置的云端 glm-5.3-flash 后端**（2026-10-21 选型结论，需阶段 0 复核是否仍可用），走 OpenAI 兼容接口。云端调用默认关闭并须由用户配置开启，发送前执行第 8 节的数据最小化和隐私校验；具体字段、推理输出语义、费用与延迟以当期接口实测为准。地址和密钥仅从本地环境变量/凭证配置读取，不提交。
- **运行环境**：目标台式机 RTX 4070 SUPER 12GB；可用显存随其他应用变化，不能用权重大小代替总运行内存。S0 记录真实峰值并冻结后端资源限制；若用 vLLM，按其版本核实 `--gpu-memory-utilization` 等参数。大型 GPU 任务前可暂停 AURA，释放模型资源需单独提供卸载机制，暂停采集不等于释放显存。

## 8. 隐私与安全

- **黑名单**：仅获取识别前台应用所需的最小身份信息；命中后不采集正文、标题、截图或键鼠内容。密码框永远不读；无法确定截图中的保护区域时禁止截图。
- **暂停**：停止所有采集/钩子，清空缓冲、工作记忆和 pending；递增生命周期代次，忽略暂停前在途任务返回，恢复不补采。已发送的云端请求无法撤回；客户端说明这一点。
- **不落盘**：截图只在内存里处理；键盘只存统计数字，原文不写日志。
- **云端边界**：决策模型优先本地运行。发送思考请求前，程序依据事件及其全部来源的隐私等级过滤输入；只要含有 `local_only`，或来源/等级无法确认，整条请求就留在本地并弃权，不得降级、自动重试到云端或只靠模型判断。云端思考默认关闭，只有用户明确配置后开启；客户端持续说明发送字段和状态、提供请求预览，遵循数据最小化；不要求逐次弹出授权框。不得发送截图、键盘原文或黑名单内容。
- **凭证**：API 密钥只由本地凭证存储/环境变量提供给客户端代码，绝不写入提示词、事件、模型日志、网页或仓库；屏幕内容不得更改模型后端和隐私配置。
- **fail-closed**：权限、隐私过滤、黑名单、暂停状态、日志完整性任一校验失败或抛错时，禁止采集敏感内容、外发请求和执行动作；报告故障并要求人工恢复，不以忽略错误继续运行。
- **外部接入**：只监听本机或局域网，需要令牌，事件同样经过隐私过滤。
- **提示注入**：屏幕内容只是"观测"，不是指令；权限检查在程序层完成，模型说什么都不能绕过。
- **本地数据**：日志和记忆存在本地，可以一键清空。

## 9. 性能与成本预算

| 项目 | 目标 |
|---|---|
| 事件 → 决策结果 | 分开报告合并/排队与推理耗时；不把等待断点计为推理时间 |
| 决策模型调用 | demo 预热后整组四题 P95 ≤2 秒，冷启动单报 |
| 思考请求 → 建议就绪 | demo 预热后思考 P95 ≤15 秒；时机等待另计 |
| 决策模型调用频率 | 只在有事件时，最小间隔 5 秒，每日上限可配置 |
| 大模型调用频率 | 受调用预算限制；demo 默认最多 100 次/日，实际值按试用调整 |
| 长驻资源 | 记录 CPU/RAM/GPU 显存、空闲占用、峰值、队列深度和运行时长；demo 阶段先测量再定预算，不把单次显存估算视为可长期常驻证明 |
| 数据出机 | 默认决策和观测留在本地；经用户配置启用云端思考时只发送最小必要且允许外发的文本 |
| demo 费用 | 云端费用由实测 token 用量和当期价格计算；价格未知时显示 token/调用数，不伪报金额 |

- 决策模型的输入覆盖和判断质量可能不足，原计划的 d3-nano 参数、视觉能力、速度和资源结论尚待复测。缓解：先用合成回放和隔离评估集；本地后端不合适时继续 Fake 回放/采集验证，按明确授权更换其他本地后端。不得自动以云端决策兜底。
- 决策模型都是新产品，接口和价格可能很快变化。缓解：统一抽象，随时可换。
- 话多或打扰：断点、表达分档、频率上限、时机判断、弃权、影子模式。
- 隐私：见第 8 节。全局键盘钩子可能被杀毒软件拦截，需要验证。
- UIA 在部分软件里读不到正文：先复测焦点/深度/无障碍设置，再评估本地 OCR 或本地视觉输入；受保护或隐私边界不明确时禁止截图，显示信息不足。
