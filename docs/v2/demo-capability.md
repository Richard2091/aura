# AURA demo：能力边界与交付标准

> 2026-11-05。本文决定 demo 做到哪里；[demo.md](demo.md) 定义实现契约，[design.md](design.md) 保留长期目标。以下均为待实现要求，不代表当前代码已有能力。

## 1. 要验证什么

**在用户没有逐次发指令时，AURA 能从连续的电脑活动中发现可能有用的帮助，选择安静、记下或等合适时机询问，用户采纳后能得到具体内容。**

需要分别验证四件事：看到了什么、判断是否有价值、什么时候表达、用户是否觉得有用。少了任何一个，都不能用另外三个的成功代替。

第一版达到“可在本人电脑上试用的实验原型”：有真实输入、真实本地决策模型、真实大模型、可操作的反馈、一天的使用记录。无需达到全天候产品、全软件覆盖、长期人格或自动执行任务的程度。

## 2. 三个里程碑

| 里程碑 | 必须做到 | 证明什么 | 不能声称什么 |
|---|---|---|---|
| M0 可回放骨架 | 合成事件、可控时钟、Fake 模型、网页时间线、全部控制分支 | 调度、暂停、限流、过期、反馈关联正确 | 真实感知或模型有效 |
| M1 真实闭环 | 在至少两类应用读取正文；本地真实决策模型；云端思考；轻提示和系统通知；采纳后展开具体建议 | 从观察到帮助的链路成立 | 已懂情绪、已个性化、能覆盖所有软件 |
| M2 试用版（本次 demo 终点） | 半天影子运行、一天正常使用；离线评估和质量报告；完成第 6 节门槛 | 在有限范围内有用、克制、可控 | 长期学习有效或具备生产可靠性 |

M0 是开发和演示底座，M2 才是本次 demo 完成。Fake 只能用于测试及明确标注的演示。界面持续显示数据来源、模型后端、实时/回放、影子/正常模式。

## 3. 最小能力与暂缓能力

**必须交付**：窗口与活动统计、至少一种可靠正文通路（UIA 或本地 OCR，图片模型按验证结果启用）、事件合并和有界队列、4 道决策题、思考与弃权、轻/中两档表达、最多一条待说内容、展示前复查、暂停/黑名单/云端过滤、反馈与运行统计。

ActivityWatch 是优先适配源；不可用时可用 Windows 前台窗口和空闲检测提供等价最小信号，报告中说明替代。四个插件不必全部同时开启才能完成 M1；正文可读、活动可判、控制可测才是验收条件。

**暂缓**：自动修代码、操作软件、发消息、付款、摄像头、麦克风、长期记忆学习、情绪诊断、向量数据库、后台反思、多 Agent 编排、独立桌面壳和复杂人格。手写小抄与反馈日志已足够支持这次验证。

“犹豫”只作为待确认的帮助机会：删除多或停顿久不能证明情绪，也不能证明消息尚未发送。没有发送状态证据时明确标为未知。

## 4. 怎么做

1. **S0 小验证**：确认模型官方仓库、许可、加载方式、题型和概率语义；用少量脱敏样本测质量和资源；验证正文采集、输入统计、通知回调。输出覆盖矩阵与失败结论。无需先装齐全部依赖。
2. **M0 回放闭环**：统一事件与关联 ID，用虚拟时钟驱动限流/过期；合成数据跑完整状态机。回放速度只影响等待，不改变业务时间。回放默认不调用网络、不弹系统通知、不接真实感知。
3. **M1 纵向切片**：先打通一个真实应用的“正文→决策→思考→轻提示→采纳”，再接系统通知、断点和第二类应用。采集继续运行时，模型任务在后台执行，旧结果不得覆盖新情境。
4. **M2 扩展与试用**：补齐隐私和故障测试，扩大评估样本，影子试用后再开表达。每一步有报告，不以固定工期代替完成条件。

本地模型不可用时继续 M0 和采集验证；图片不支持时先试本地 OCR + 文本输入。不得自动切到云端决策或上传屏幕。更换已决定的本地模型选型需要记录评估理由；若要求改变数据出机边界，另行取得明确授权。

## 5. 三分钟演示脚本

使用合成或人工脱敏数据，时间线展示五段：

| 时间 | 内容 | 观众能看到的证据 |
|---|---|---|
| 0:00–0:30 | 普通浏览和窗口切换 | 事件存在，判断不值得深入，未调用思考模型 |
| 0:30–1:10 | 终端报错或文档中的明确问题 | 证据摘要、决策、准备好的具体建议 |
| 1:10–1:45 | 用户继续输入，随后停顿 | 内容先暂存，当前状态允许后才展示 |
| 1:45–2:15 | 问题已消失或内容过期 | 旧念头被丢弃，日志说明原因 |
| 2:15–3:00 | 采纳一条建议、拒绝一类建议、暂停 | 可展开内容，反馈关联原念头，暂停后不再采集 |

这是控制逻辑演示；另用真实 M1 操作展示模型能力。演示数据的预期结果是测试标签，不能作为真实模型输入或写入业务分支。压缩的回放时间不用于报告真实延迟。

## 6. 做到什么程度算完成

以下是本项目初始门槛，尚非实测成绩。调整门槛要在评估前留记录，不能看到结果后降低标准。

| 维度 | M2 完成条件 |
|---|---|
| 真实感知 | 至少两类应用（如终端/编辑器与浏览器/文档）各 10 个正文样本，至少 8 个足以辨识任务；保留失败项，不只统计窗口标题 |
| 控制正确性 | 所有暂停、黑名单、影子、输入中禁止通知、限流、过期、旧结果丢弃、云端过滤案例全部通过；测试与试用中观察到的违规次数为 0，不宣称测试穷尽所有风险 |
| 离线模型质量 | 独立测试集至少 60 个片段：应帮忙、应安静、信息不足各至少 20 个，另备调参集；真实模型帮助精确率 ≥80%，召回率 ≥60%；ask 为正预测，信息不足时 ask 计误报；报告混淆矩阵、分母和应用分布 |
| 数据隔离 | 调参集与评估集分开；相邻片段/同一次问题归同一集合；标签、预期结果不进入模型上下文 |
| 具体帮助 | 至少 10 个应帮助片段中，7 个生成的建议由本人评为与当前内容相关且可用；只有“要帮忙吗”不算具体帮助 |
| 性能 | 至少 30 组本地四题决策和 20 次思考：P95 分别 ≤2 秒/≤15 秒（均为预热后的真实墙钟时间）；等待断点另计，冷启动单报 |
| 资源 | 连续运行记录至少 2 小时的 CPU/RAM/显存、调用量、超时和队列峰值；8 小时试用无未处理崩溃、无持续队列增长；显存预算在 S0 按实际后端冻结 |
| 使用体验 | 先至少 4 小时影子运行，再累计 8 小时正常使用；默认通知上限 6 条/日、间隔 15 分钟；获明确评价的建议累计至少 10 条，其中有用比例 ≥70% |
| 样本不足 | 若一天没有 10 条明确评价，继续累计试用或报告证据不足；不得为凑指标主动制造通知，也不能把未反馈算负面 |
| 可复现 | README 能指引新环境启动；合成回放不需密钥/GPU；真实运行有依赖清单、覆盖矩阵、评估集版本、模型版本和报告 |

稳定性和隐私为硬门槛；质量不足时结论写“链路已通、模型质量未达标”，不要用 Fake 成绩或只挑成功案例宣称 M2 完成。

## 7. 本机探测能说明什么

2026-11-05 会话中的一次有限探测记录：RTX 4070 SUPER 12GB，查询时显存使用约 2.4GB；WSL2 Ubuntu 已存在且停止；ActivityWatch 本地接口未连接。Python 可通过 `py` 找到 3.10 和 3.14，但尚无项目虚拟环境。

浅层 UIA 遍历在当时的浏览器只读到界面文字（约 143 字），QQ 未返回文字；PIL 全屏截图 1920×1080 单次约 40ms。这些结果只反映当时窗口、遍历深度和无障碍设置，**不能证明应用永远不可读，也不含 OCR/视觉推理开销**。没有证据确认 WSL 内是否已装 vLLM。

S0 应复测前台正文、UIA 焦点/深度/无障碍设置、本地 OCR、前台窗口截图、多显示器/DPI、密码区域保护。按应用选择信息充分且成本较低的路径，保留 UIA 优先、截图按需的策略；不据单次测量改成持续截全屏。
