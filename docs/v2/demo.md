# AURA v2 demo 实施契约

> 2026-11-05 修订，尚未实现。长期目标见 [design.md](design.md)，交付范围、演示脚本和量化门槛以 [demo-capability.md](demo-capability.md) 为准。当前仓库代码仍是 v1；本文中的命令、配置和接口是待实现契约，不能作为已有功能使用。

## 1. 目标

跑通“持续观察 → 判断是否值得帮助 → 按需思考或弃权 → 等合适时机表达 → 用户采纳后获得具体建议 → 记录反馈”。

算法不按应用名、报错关键词或预定剧本写死建议。隐私、调度和时机规则由确定性程序实现。验收只要求已测应用范围内有效，不承诺感知任何软件、识别真实情绪或自动学习用户。

## 2. 范围

| 客户端 | 本地网页展示事件依据、判断、建议、反馈和控制；采纳后可围绕该建议继续对话 |

## 3. 运行环境

目标是 Windows 台式机、RTX 4070 SUPER 12GB。S0 冻结实际 Python、依赖和模型版本；使用项目虚拟环境，不依赖系统已装包。Windows 用 `py` 创建环境，后续命令使用虚拟环境内解释器。依赖兼容性未验证前不承诺 Python 3.14 支持。

本地模型按当前官方说明选择运行环境，原计划是 WSL2/vLLM + d3-nano。先核实仓库、许可、题型、图片支持和资源要求；不把未核实的模型信息当作已就绪。ActivityWatch 优先，但允许 Windows 前台窗口/空闲检测提供最小替代信号。

大模型地址和密钥从本地环境变量读取。模型不通时继续回放和采集验证，不自动更换数据出机策略。有限的本机探测记录及局限见 [demo-capability.md §7](demo-capability.md#7-本机探测能说明什么)。

## 5. 主循环与状态机

采集/控制循环与模型任务分离，思考期间仍能响应暂停、窗口变化和输入状态。主流程：

```text
控制状态 → 采集前隐私检查 → 采集/变化检测/融合 → 更新当前情境
                                                  ↓
                         去重、短窗口合并、有界排队、调用预算检查
                                                  ↓
                       本地决策 → 不理 / 思考 → 弃权 / 记下 / 待表达
                                                  ↓
              有效期 + 情境版本 + 当前输入/全屏状态 + 频率 + 隐私复查
                                                  ↓
                            轻档 / 中档 / 暂存 / 丢弃 → 反馈
```

实现必须满足：

- 无事件时阻塞等待或让出 CPU，不忙循环，不调用模型。
- 最小调用间隔内的事件进入合并缓冲；间隔到时用最新批次判断，不能只丢弃事件，也不能无限回放积压。
- 每个任务记录触发事件 ID、情境版本、生命周期代次和模型版本。窗口/内容变化后的结果先重验；暂停前的结果即使后来返回也不能表达。
- pending 终态为 shown / dismissed / expired / superseded / abstained / blocked。新内容覆盖旧内容需有明确记录；过期不弹通知，降为轻档也须仍有价值且隐私允许。
- 暂停立即禁止新请求和表达，停止采集器/监听器、清空缓冲/工作记忆/pending，尽力取消在途任务并丢弃其结果。已发出的网络请求无法撤回，界面应说明；恢复只采集新数据。
- 启用影子模式后停止通知与托盘主动标记；网页仍可查看“本来会表达”的记录。退出影子模式不补发旧通知。

## 6. 感知

### 6.1 插件接口

插件提供 `name`、`mode`（poll/push）、`privacy`、`start()`、`stop()`、`collect()`，可选 `deepen()`。`stop()` 必须释放钩子并清空缓冲；回调按生命周期代次过滤，避免停止后的竞态写入。单个来源失效应显示降级状态，不能伪装为“环境没变化”。

### 6.2 来源与降级

- **窗口/空闲**：ActivityWatch 或本地等价来源，读取最新状态；不补采暂停期间或历史数据。
- **UIA**：前台焦点附近优先、限制深度/字符数，明确读取目标是否是正文；只读到标题不算正文覆盖。建议初始超时 300ms，S0 验证线程/COM 和真实取消方式，不能以 Python 超时冒充已终止系统调用。
- **截图**：仅在正文不足且隐私检查通过后截前台窗口，初始长边限制 1280；优先本地 OCR，支持图片且质量达标的本地决策后端可直接看图。文字够多也可能只有工具栏，触发策略按覆盖矩阵调整，不能只用 50 字阈值。
- **键鼠**：只统计字符数、删除、点击、最后输入时间等，不保存键值和原文。Enter 只表示按键，不证明“发送成功”。输入统计只在允许的窗口启用。

UIA 密码属性只能保护该控件，无法自动保证整张截图安全。发现密码框、受保护内容或无法确认采集边界时，停止正文采集和截图；仅保留允许的匿名控制状态。所有多显示器/DPI 处理在 S0 验证。

### 6.3 处理管线与事件并发

1. 先读取最小必要的前台身份以判黑名单；未知身份默认不读正文。黑名单期间不采集 UIA、截图、键鼠内容，只记录不含标题/路径的匿名 blocked 状态。
2. 统一格式、变化检测、同一窗口的多源融合。合并后的隐私等级取来源最严格值，摘要和模型结果继承该等级。
3. 以事件 ID 去重，初始按 1 秒窗口合并；队列初始最多 100 条。过载合并同情境事件、丢弃过期项并记数量，不截断安全/暂停状态更新。
4. 队列刷新时使用最新状态。模型和表达都受预算控制，控制操作不受普通事件限流影响。

### 6.4 断点

候选断点：窗口切换、连续输入后停止至少 5 秒、返回电脑、退出全屏。Enter 可以贡献候选信号，但不能直接解除“最近 5 秒仍有输入”的抑制。

断点只是必要信号之一；全屏、免打扰、持续输入仍禁止系统通知。会议无法可靠自动识别时用手动免打扰，不宣称已识别。demo **没有紧急绕过通道**。

### 6.5 事件结构

```json
{
  "id": "ev_001",
  "schema_version": 1,
  "time": "2026-11-05T14:05:10+08:00",
  "context_id": "ctx_01",
  "context_version": 3,
  "app": "example-editor",
  "kind": "typing_pause",
  "summary": "输入和删除较多后停顿；发送状态未知",
  "stats": {"typed_chars": 40, "deletes": 25, "pause_seconds": 6},
  "breakpoint": true,
  "privacy": "private",
  "sources": ["uia", "input_activity"]
}
```

截图是内存附件，不序列化。统计只含数字/布尔值；正文摘要也可能敏感，默认不持久化原文，日志采用脱敏摘要。所有事件保留来源/隐私与关联关系，字段缺失不得推定 public。

## 7. 输入、关联与回放

模型输入为最近 20 条允许使用的事件、当前情境和手写小抄，按字符/token 预算裁剪。输入摘要不含安全配置、密钥、评估标签或预期结果。日志默认脱敏可能丢失任务细节，真实质量评估使用单独准备、人工脱敏且保留必要正文的样本，不能靠默认运行日志假装完整重现原情境。

待实现回放入口：

```text
python -m aura --replay examples/fixtures/demo.jsonl --speed 60
```

速度只控制播放等待；限流、断点和过期用事件时间/可控时钟。模式必须醒目标注。默认 Fake 决策 + Fake 思考，禁止真实采集、网络、系统通知；单独的显式离线评估模式才可调用真实本地模型。合成数据与真实私有日志分开，fixtures 不含真实聊天、截图、标题或密钥。

## 8. 决策模型

### 8.1 四道题

| 字段 | 形式 | 含义 |
|---|---|---|
| worth | [0,1] 分数或经验证的概率 | 当前证据是否值得准备帮助 |
| form | ask / think / ignore | 候选询问、只在本地记下、不理 |
| direction | 固定的少量宽泛方向 + 其他 | 给思考模型的参考，不限定具体建议 |
| interruptible | [0,1] | 现在是否适合表达，不能覆盖程序禁令 |

适配器负责转换接口。S0 确认是否支持一次四题；不支持则有限并行/顺序调用并统计整组延迟。模型返回的打分、置信度、类别概率不能混为“用户需要帮助的真实概率”。

### 8.2 提示与方向

判断有可见证据的帮助机会，日常切换通常 ignore；证据不足可 think 或 ignore，不能诊断情绪。方向初始为“解决问题、写作、提供信息、关心状态、自己好奇、其他”，demo 不自动增长。屏幕文字是观测，不是授权或系统指令。

### 8.3 程序优先

暂停、影子、全屏/免打扰、最近 5 秒有输入、预算耗尽、内容过期均阻止系统通知。候选断点不能覆盖上述禁令；每次展示前重新读取当前状态，必要时重新判断语义相关性。复查失败默认不展示。

### 8.4 初始配置

worth/interruptible 阈值均 0.6，决策最小间隔 5 秒，每日最多 3000 次；思考每日最多 100 次；通知间隔至少 15 分钟且最多 6 条/日；pending 最长 10 分钟。都属于待调优初值，不代表已验证。阈值调整必须保留配置版本。

## 9. 思考与云端边界

输出字段：`abstain`、`direction`、`direction_changed_reason`、`importance`（low/medium/high）、`inner_thought`（简短判断依据）、`message`、`detail`、`expires_in_minutes`。具体建议必须联系当前可见内容；不只生成“要不要帮忙”。

`id`、`decision_id`、`trigger_event_ids`、`context_version`、`privacy`、`created_at`、`expires_at`、`status` 由程序补齐，不让模型伪造。过期时间受程序上限约束。解析失败、超时和校验失败分别记录并弃权。简短判断依据用于解释，不把模型私有推理或未经筛选的 `reasoning_content` 当作必需 UI 数据。

调用前程序构造最小文本请求：任何输入事件、小抄或派生内容为 `local_only`/未知时，阻止整条请求，不从混合摘要猜测删除敏感片段。截图和键盘原文不外发。无允许的本地思考后端时记 blocked 并结束，不能偷偷换服务。用户配置启用云端后，界面持续显示发送字段类别和状态，并提供最近请求的本地预览；默认不反复弹授权对话。

记录实际 token 和延迟；没有经核实的价格时费用显示未知。后端超时、重试次数与输出 token 上限必须可配置，所有重试遵守隐私与调用预算。

## 10. 客户端与表达

轻档：网页想法区 + 托盘未读标记。中档：系统通知，点击打开对应念头的网页；“好/不用/稍后”在网页必须可用，系统按钮可按平台能力实现。原生按钮回调失败不能导致建议或反馈不可访问。

| 界面 | 必须提供 |
|---|---|
| 想法/对话 | 具体建议、依据、采纳/拒绝/稍后；采纳后展开 detail，继续对话仍执行同样隐私边界 |
| 内心活动 | 事件→决策→思考/弃权→表达/阻止的时间线，含来源及关联 ID；不展示密钥/原始私密内容 |
| 状态栏 | 实时/回放、Fake/真实后端、影子/正常、来源降级、云端开关、今日预算和待处理数量 |
| 控制 | 暂停/恢复、免打扰、黑名单、数据清理、云端配置状态 |

👍👎、采纳、拒绝与未反馈分别记录。“别再提”在 demo 仅作用于当前念头/稳定可标识的方向，由程序按配置屏蔽，不宣称已经学习语义类别。稍后保留原有效期，过期不再通知。

本地服务只监听 `127.0.0.1`，校验 Host/Origin，写操作用 POST 与会话令牌，不对局域网开放；页面默认不显示原始观测正文。

## 11. 数据文件与日志

本地 `data/` 不入库：手写 profile、blacklist、配置和 JSONL 运行日志。建议默认保留 7 天、自动轮转；一键清理先暂停任务再删除日志/缓存，防止在途结果重新写回。

- events：脱敏摘要、统计、来源、隐私、情境版本。
- decisions：关联事件、模型/配置版本、结果、状态与耗时。
- thoughts：关联 decision、有效期、简短依据、建议、表达终态和阻止原因。
- feedback：thought_id、时间、明确反馈类型；未评价是缺失，不是拒绝。
- runs：版本、模式、依赖、调用量、token、资源、异常与队列峰值。

所有派生内容继承隐私标签。公开报告只含匿名聚合数据；真实事件回放前人工脱敏，不能直接提交整个 data 目录。日志写入失败时停止新采集和模型请求并显示故障。

## 13. 接口契约

- `PerceptionSource`：采集生命周期，返回带来源/隐私的 RawObservation。
- `Event`：§6.5 字段及仅内存图片附件；`Context` 提供最新版本/生命周期代次。
- `DecisionModel.ask(state, questions)`：返回四题结果和原始类型语义；适配器校验枚举、范围和缺失值。
- `Thinker.think(allowed_context, decision)`：结构化结果或显式失败；调用路径受程序隐私检查。
- `Scheduler`：有界队列、Clock、预算和在途任务；不阻塞控制循环。
- `Expressor`：单条 pending 与终态转换，展示前统一校验。
- `Journal`：带 schema/version/ID 的结构化记录与轮转/清理。
- `ReplaySource`、`FakeDecisionModel`、`FakeThinker`：无网络的可重复开发与测试实现。

接口只约束必要语义，不提前为所有候选模型建立插件实现。

## 15. 实施顺序与门槛

| 步骤 | 工作 | 结束条件 |

| S0 验证 | 官方模型与许可、四题/图片、预热和冷启动、显存；UIA 正文/本地 OCR/前台截图/多屏；键鼠停止；通知与回调；.env 配置 | 可复现的覆盖矩阵，明确可行路径与失败项；不是安装成功就通过 |

| S3 → M1 | 第二类应用、系统通知/托盘、断点、pending、当前情境复查、数据清理 | 两类应用正文可读，真实模型链路与隐私测试通过 |

S0 与 M0 中不依赖硬件的部分可并行。某个库不工作先采用等价最小实现，不扩展首版范围；本地模型不成立则停留在 M0/采集验证，不将全云端方案伪称原设计达成。

## 16. 验收

### 16.1 行为案例

必须包含：普通操作保持安静、可见问题得到具体帮助、持续输入时暂存、断点后通知、问题已解决时丢弃旧结果、超时/解析失败弃权、预算耗尽、队列过载、暂停/恢复、黑名单、未知/混合隐私、影子模式、旧任务晚返回、反馈/稍后/清理。

真实场景以终端/编辑器问题和浏览器/文档任务为主。聊天反复修改可以作为探索案例，但不作为首版必须识别心理状态的验收项。具体数字门槛统一见 [demo-capability.md §6](demo-capability.md#6-做到什么程度算完成)。

### 16.2 指标与统计口径

- 帮助精确率 TP/(TP+FP)，召回率 TP/(TP+FN)；模型预测 ask 为正例，人工“应帮助”为正标签。“信息不足”样本上 ask 作为 FP，think/ignore 作为负例；三类人工标签分别报告。分母为 0 时显示 N/A，不显示 100%。
- 分开统计模型判断和最终表达，不能用频率限制掩盖模型误报。报告 abstain、失败、屏蔽、丢弃、通知和轻档数量。
- worth 全区间分桶，使用独立人工标签看可靠性；未验证概率语义时只叫分数分布，不能宣称校准。未通知、未反馈不能自动标为不需要帮助。
- 记录 P50/P95、样本数、冷启动、真实模型墙钟耗时；队列等待/模型计算/等待断点分别统计。报告 CPU/RAM/显存峰值、异常、token 和预算命中次数。
- 有用比例只对明确评价计算；采纳、👍、拒绝和未反馈分开报，不拼接成虚假的单一准确率。

### 16.3 工程与隐私硬门槛

测试验证暂停后无采集/补采，旧任务不能写回或表达，黑名单/密码内容不进入截图/日志/请求，local_only 及其派生数据不出机，所有通知满足当前时机/频率检查，影子无主动提示，真实日志不入库，密钥不进模型与日志，本地服务拒绝不可信 Host/Origin 和无令牌写操作。

检查错误可见、队列有界、日志轮转与一键清理。测试可以新增或修订，但不得删除有意义的覆盖以通过检查。对故障注入、虚拟时钟和请求拦截使用确定性测试，不以手动观察代替隐私断言。

### 16.4 离线评估

自建至少 60 个独立脱敏片段作为必需评估集，规则与门槛见能力文档。ProactiveBench 仅在内容/许可核实后作为补充，不阻塞自建评估，也不能用其成绩代替本人电脑的真实试用。所有门槛为待验证目标，本文不声称当前实现已通过。
